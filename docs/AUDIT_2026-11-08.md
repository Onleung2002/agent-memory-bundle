## Audit 後續發現（verify 輪產出）

- **A-1（原 MEDIUM，mini round 已修）**：同 bundle resuscitate overwrite 破壞 supersession chain——`360f1e1` 改為 fresh-path id collision 路由 `_reissue_receipt`；controller 親手重現 bug → 修後 r3/r4 byte-intact、恰好一個 ok:True tail、同 mode ×3 循環零 collision（ATK3 兩 mode pinned）。
- **A-2（LOW，backlog，範圍擴大）**：silent-skip pattern 確認多一處——`recover()` 對 unreadable/NaN-poisoned manifest **靜默 skip**（broad `except ValueError: continue`）；typed gate 仍喺 `_read_recovery`/`recovery_removals` 及下游 delete/verify fire（pins 已證）。修法：skip 計數入 `_self_check`/chain walk problem，或收窄 except。
- **A-3（LOW，backlog）**：一個毒 manifest 塞住全 root deletes（fail-closed 正確、availability trade-off）——SECURITY.md 補一句。
- **A-4（LOW，backlog）**：`_safe_id` 尾底線摺疊 non-injective（`a`/`a_` 撞）——collision guard 令 fail-closed，sha256 檔名係穩陣修法。
- **A-5（LOW，已 pin）**：`json_loads_strict` parse gate 原先無 test observable（M4c mutation false-green）——`dbc8413` 8 條 pins（evidence/recovery/journal/receipt/manifest/ack 邊界 + gate unit），M4c 重跑紅×5。
